# 독립 채택 검증

중요한 결론을 채택하기 전에 `scripts/th-adopt.sh 작업폴더 "결론 한 줄"`을 실행한다. 기본 검증자는 코디네이터와 다른 계열의 Codex Terra 한 명이다. `--two`를 지정하면 기존 Sol과 Argon 두 명이 검증한다. 기본 모델은 `TH_ADOPT_MODEL`로 바꿀 수 있다. 코디네이터가 최종 결정을 내린다.

검증자는 작업의 `task.md` 원문과 결론, 작업 폴더의 산출물과 원본을 살펴보고 스스로 판정 기준을 세운다. 원본은 기본적으로 작업 폴더가 속한 Git 저장소이며 `--source 경로...`로 지정할 수 있다. 필요한 파일과 구간만 읽고 15분, 문맥 60,000 토큰 이내로 검토한다. 결과는 40줄 이내로 쓰며 끝 두 줄에 반례 한 줄과 PASS, FAIL 또는 INSUFFICIENT_EVIDENCE를 기록한다.

완료되면 감시기가 결과를 합산해 inbox에 `채택 검증 PASS|FAIL|보류 — 결론 — 반례: ...` 한 줄을 보낸다. FAIL이나 보류라면 검증자의 VERDICT.md를 열어 상세 근거를 살펴본다. 작업 폴더의 `.th_adopt/CROSSCHECK.md`에도 결과가 기록된다. 검증 중 산출물이나 원본이 바뀌거나 실행에 실패하면 보류한다. 실행은 기존 th-launch 예산과 동시 실행 제한을 따른다.

일반 워커도 검증 재료가 없어 상태 외 모든 검사가 생략되면 `WARN 검증 없음`으로 표시한다. 상태가 실패라면 FAIL이 우선한다. `ths` 상단에는 최근 7일의 검증 없는 완료 건수를 프로젝트별로 표시한다.

`scripts/th-crosscheck.sh verdict 폴더`와 `decide 폴더 --adopt --reason 이유` 또는 `--reject`는 새 `.th_adopt` 폴더에도 사용할 수 있다. 보류 결과를 채택하려면 `--override-reason`이 필요하다. 기존 `start`, `verdict`, `decide` 절차도 유지된다. 새 TH-D 제목을 포함하는 push의 `Crosscheck:` 트레일러 또는 기록되는 예외 사유 관문도 유지된다.

해시 검사는 시작과 종료 사이에 변경 후 원상 복구한 내용이나 외부 정보 유입까지 막지는 못한다. 해시 비교는 작업 산출물과 원본을 대상으로 하되 감시 기록, `.claude`, 가상환경 및 원본 저장소의 다른 `_outputs`는 제외한다. 접근이 제한된 명시 원본은 검증자별로 복사해 비교한다. 심볼릭 링크는 링크 경로만 비교하므로 연결 대상의 내용 변경은 별도로 확인해야 하며, 제한된 원본의 링크는 허용하지 않는다. 접근 통제는 운영체제 샌드박스가 아니라 워커 지시와 경로 제한, 사후 비교에 의존한다. th run/repl, SDK와 protocol은 독립 채택 시점을 정의하지 않으므로 자동 호출하지 않는다.
