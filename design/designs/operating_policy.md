# 공통 운영 정책

사용자의 현재 지시와 이미 받은 권한을 우선한다. 이 문서는 기본 운영 기준이며, 저장소별 데이터 경로·공개 API 계약은 해당 프로젝트 지시를 따른다. 동일 정책을 설정·스킬에 다시 작성하지 않는다.

## 역할과 작업 크기

- Orca의 대화형 코디네이터는 Claude로 운영한다. Codex는 워커로 유지한다. 라이브러리의 기존 provider 및 SDK 지원은 제거하지 않는다.
- 조율자는 범위·우선순위·지시서·검증·보고를 담당한다. 구현·장시간 실행은 워커에 위임한다. 사용자가 승인한 작고 명확한 문서·설정 수정은 위임 비용을 고려해 직접 처리할 수 있다. 이미 위임한 파일은 중복 수정하지 않는다.
- 작은 변경은 워커 하나, 설계와 독립 검수가 필요한 변경은 MODE C, 대안 비교를 요청한 경우 MODE A, 작업 인계는 MODE B를 선택한다. 사용자가 지정한 MODE를 바꾸지 않는다.
- 기본 코드 워커는 Codex Terra medium이다. 복잡한 구현은 Terra high, 핵심 분석은 Sol medium, 중요한 설계·어려운 오류는 Sol high를 사용하며 상향 이유를 남긴다. agy는 단순·대량·비코드 작업 및 Codex 쿼터 잠금 시 대체에 쓴다. Claude 워커는 사용자 명시 요청 때만 사용한다. 구체 모델 ID와 기본값은 실행 템플릿·전역 설정이 정한다.

## 읽기·비용·상태

- 규칙과 설정은 작업 시작에 한 번 읽는다. 반복 처리마다 같은 문서를 다시 읽거나 에이전트를 새로 띄우지 않는다. 압축 후 필수 상태 복원과 승인된 정책 배포의 변경분 확인은 필요한 부분을 한 번 읽는다.
- 검색으로 범위를 좁힌 뒤 필요한 코드·diff를 읽는다. 리뷰에 필요한 diff까지 금지하지 않는다. 큰 로그는 끝부분과 필요한 구간을 읽고 출력 상한을 둔다.
- 워커 지시서는 목표, 읽을 문서의 경로·절(없으면 없음), 쓰기 범위, 산출물, 완료 기준과 검수 명령을 포함한다. 코드·데이터 탐색은 작업에 필요한 범위에서 허용한다.
- 상태는 STATUS(시각·단계), WORKLOG.md(현재 목표·방법·완료/잔여·문제·경로), DONE/FAILED로 전달한다. 채팅의 완료 주장만으로 성공을 판정하지 않는다.
- 코디네이터는 시작·압축 직후·긴 작업 전에 current_status를 복원한다. 내장 run/repl·SDK 코디네이터 일지는 전용 run_dir/journal에 쓰고 워크스페이스 .claude 일지는 외부 코디네이터가 소유한다. 스크립트의 반복 사건 기록을 중복 작성하지 않고 판단·원인·결정은 work_log에 남긴다.
- LLM으로 폴링하지 않는다. Claude 코디네이터는 세션별 inbox waiter 하나를 사용하고, 상태는 요청 시 한 번 조회한다. `ths -w`는 별도 터미널에서 사용한다.

## 재실행·종료·검증

- 긴 작업은 `th-job-start.sh`로 분리하고 본 작업 PID와 단계 기록을 남긴다. 직접 setsid로 실행하지 않는다.
- 완료 단계는 다시 실행하지 않는다. 단계별 replay=safe/never/inspect 기록을 따른다. 학습·push·merge·삭제·외부 쓰기는 never, 읽기·반복 가능한 검사는 safe, 불명확하면 inspect다.
- 원인 불명 실패는 먼저 진단한다. 선언된 복구 정책에 따른 재개와 같은 명령의 무근거 반복을 구별한다. 쿼터·인증 오류와 사용자 중단은 자동 계속하지 않는다. 같은 원인으로 반복 실패하면 기존 상한에서 멈추고 작업을 분할한다.
- 프로세스는 저장된 시작 신원을 확인한 뒤 종료한다. PID만 같다는 이유로 종료하지 않는다. 분리된 job 그룹은 보존한다.
- 검수는 실제 실행 결과로 판정한다. 검사 재료가 전부 SKIP이면 WARN이다. 검사 입력이 선언되지 않은 임의 셸 검수는 매번 실행한다. `verify_inputs.json`에 모든 파일 입력을 선언한 경우에만 내용 해시로 캐시하며 `th-verify.sh --force`로 재검수한다.
- 중요한 결론은 기본 검증자 한 명이 원본으로 반증한다. 채택 기록은 검토한 변경과 최신 결정을 가리켜야 한다. 결과 불충분을 PASS로 표시하지 않는다.
- 이미지 모델 입력은 기본 차단하고 사용자의 명시 요청 범위에서 허용한다. 기존 승인 범위를 작업 밖으로 확대하지 않는다.

## 적용·배포

- 공통 자원 정책은 th-launch와 run/repl·SDK·protocol의 실제 워커 생성 경로에서 공유한다. 감시·상태 조회는 실행 정책을 관찰하고 직접 워커를 추가하지 않는다.
- Jev 도구 선택은 내장 조율자에만 붙는다. 모델 등급·실패 원인 권고는 여러 실행 경로에 붙으며 모델이나 재시도를 임의로 바꾸지 않는다. graft는 선택 기능이며 th-launch에는 아직 연결되지 않는다.
- 문서 이관·일일 보고·보관은 별도 maintenance 프로세스에서 수행한다. 감시기는 유지보수 완료를 기다리지 않는다.
- 기능 수정은 검증·push 후 전역 실행 경로·정책·스킬과 워크트리에 반영한다. 사용자 수정은 보존하고 충돌·미반영을 배포 결과에 표시한다. 전역 명령은 정본 설치를 사용한다.
- 새 프로세스는 최신 코드를 사용한다. 실행 중 Claude 세션에는 다음 사용자 입력에서 정책 변경을 한 번 전달한다. 이미 읽은 코드·프롬프트가 소급 교체됐다고 주장하지 않는다. 분리된 실행 작업을 강제로 재시작하지 않는다.
