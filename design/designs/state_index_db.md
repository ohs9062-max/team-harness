# 상태 색인 DB

`<watch_dir>/th.db`는 작업 상태를 SQL로 살펴보기 위한 지워도 되는 사본이다. 기존 장부와 작업 폴더가 정본이며 DB가 실행이나 판정을 바꾸지 않는다. `TH_WATCH_DIR`가 우선이고 기본 경로는 기존 감시 경로다. `th-db.sh update`로 즉시 갱신하고 `th-db.sh sql 'SELECT ...'`로 최대 200행을 읽는다. SQL은 읽기 전용 연결이며 SELECT와 WITH로 시작해야 한다. 유지보수는 30초 주기로 갱신하며 `TH_STATE_DB=0`으로 끌 수 있다.

## 기록과 범위

처음 생성할 때 `started_at`을 UTC로 기록한다. 그 이후 시작한 시도와 그 이후 변경된 작업만 기록한다. 사건 줄은 줄에 포함된 시각이 기준 이후인 경우만 기록하므로 시각이 없는 줄은 제외한다. 기존 작업의 변경은 해당 표식의 파일 수정 시각으로 감지한다. 기존 집계의 분·토큰·결과 계산을 재사용한다. 여러 시도 중 시작 시간이 기준 전인 시도는 가져오지 않는다. 파일의 수정 시각이 보존된 외부 복사나 등록 이전에 사라진 작업은 누락될 수 있다.

| 테이블 | 내용 |
| --- | --- |
| meta | 스키마 버전과 수집 시작 시각 |
| tasks | 경로, 소유자, 작업 키, 종류, 최초 관찰, 상태와 마지막 단계 |
| attempts | 시도별 워커, 모델, 시작, 분, 토큰, 결과와 override |
| failures | 실패 표식별 분류와 최대 300자의 원인 |
| events | 감시 및 등록 소유자 inbox의 시각이 있는 사건, 최대 400자 |
| adoptions | 발견된 채택 검증 폴더의 주장과 검증자별 판정·반례 |
| ingest_state | 사건 파일별 inode와 바이트 위치 |

줄 파일은 마지막 완성된 줄까지 위치를 저장하고 다음 갱신에서 이어 읽는다. 교체나 잘림을 감지하면 처음부터 다시 읽되 기준 전 줄을 버린다. 같은 출처의 같은 사건 줄은 해시로 중복 제거한다. 동일한 내용의 실제 반복 사건은 하나로 합쳐지는 한계가 있다. WAL과 busy timeout을 사용한다. 읽을 수 없는 파일은 경고 후 건너뛰며 유지보수 갱신의 예외는 유지보수 로그에 남기고 다른 작업을 계속한다. 정본을 수정하지 않으므로 DB 삭제 후 재생성하면 그때부터 새로 수집한다.

## 적용 경로

| 경로 | 기존 흔적과 연결 | 검증 및 제한 |
| --- | --- | --- |
| th-launch | tasks 등록부, usage 기록, 작업 표식; 유지보수가 수집 | 임시 등록부 및 실패 테스트. 감시 등록 이전 중단은 누락 가능 |
| th run/repl, SDK | 공유 admission 예약과 유지보수 시작; 작업 표식 | 등록부 또는 활성 admission에 작업 경로가 있을 때 수집. 예약 해제 후 등록부에 없는 작업은 누락 가능 |
| protocol | 유지보수 시작과 공유 admission; 하위 실행 경로의 장부 | 등록되지 않고 예약이 해제된 작업은 누락 가능 |
| watchd/watch/ths | watchd가 유지보수 시작, tasks 및 events | 사건 증분 테스트; watch/ths 자체는 DB를 직접 갱신하지 않음 |

채택 검증은 등록된 작업 경로가 검증 폴더 또는 그 직계 검증자 폴더일 때만 발견한다. 등록되지 않은 검증 폴더는 탐색하지 않는다. 유지보수 소유자 등록부는 inbox 출처 발견에 사용한다. 사용량 원본에 없는 모델·토큰·비용은 추정하지 않는다. 비용 열은 원본에 일관된 비용이 없어 이번 단계에서 제공하지 않는다.
