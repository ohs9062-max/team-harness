# 전역 자동 적용

사용자가 th cord와 ths만 사용해도 실행 관찰과 이력 조회가 적용되어야 한다.

- 이미 전역 적용: 기존 hook과 공유 유지보수.
- 실행 후 관찰: 동일 사용자의 프로세스와 환경을 읽어 출처를 복원하고 색인한다. 원본 등록부와 실행 제어는 변경하지 않는다.
- 실행 전 가로채기: 다음 단계에서 PATH 앞 shim을 두며 처음에는 판정만 기록하는 관찰 모드로 운영한다.
- 명시 명령: ths, th-db, th-why로 조회한다.

예산 초과는 경고 후 실행하고 상한 대기가 30분을 넘으면 inbox에 알린다. 반드시 실패할 지시서 오류만 실행 전 정지한다. 같은 일의 반복 실패 2회에 정지하고 실행 깊이를 제한한다. 관찰로 편입된 작업은 자동 재실행하지 않으며 세션별 차단기는 처음에는 기록만 한다.

1차는 실행 후 관찰, 상태 DB와 코디네이터 자동 조회다. 실행 전 제어는 다음 단계다. 롤백 기준은 `checkpoint-20261112-pre-global` 태그다.

## 2차: 실행 전 관찰

shim은 기본 꺼짐이다. 상태 DB와 실행 후 관찰을 운영하고 사용자가 승인하면 `th-sync.sh --enable-shim`으로 켠다. `~/.team-harness/shim/enabled` 표식이 있는 동안 이후 전역 적용도 shim을 유지한다.

shim 설치는 `~/.team-harness/shim/bin`에 저장소의 `codex`, `agy`를 링크하고 `.bashrc`, `.profile`의 관리 블록으로 PATH 앞에 추가한다. 기존 셸에는 적용되지 않는다. `th-sync.sh --status`의 `shim`으로 확인하고 `th-sync.sh --remove-shim`으로 관리 블록과 해당 링크를 제거한다. `claude`는 변경하지 않는다.

대화형 codex, `th-launch.sh` 자손, `TH_SHIM=0`은 기록 없이 통과한다. 직접 비대화형 실행은 기존 정책 판정과 지시서 검사를 관찰하고 같은 PID로 원래 프로그램을 실행한다. stdin은 읽지 않으며 점검 불가로 기록한다. 예외나 잠금은 실행을 막지 않는다. `TH_SHIM_MODE`와 관계없이 이번 구현은 관찰만 수행한다. 깊이는 `TH_SHIM_DEPTH`로 전달한다. DB에 프롬프트 자체 대신 해시를 저장한다. 반복 실패는 상태 DB에 색인된 동일 작업 실패만 셀 수 있으며 직접 실행의 종료 결과는 exec 이후 알 수 없다. 관찰된 작업은 자동 재실행하지 않는다.

| 경로 | 적용 위치 | 확인 |
| --- | --- | --- |
| 직접 codex exec / 비대화형 agy | PATH shim | 가짜 실행 파일과 실제 셸 테스트 |
| th-launch | 기존 실행 전 정책, shim 통과 | 조상 우회 테스트 |
| 내장 조율자·SDK·protocol | 기존 정책 및 직접 CLI 호출 시 shim | 기존 회귀 테스트 |
| ths / watch | DB 관찰 건수 표시 / 기존 프로세스 관찰 | 상태 출력 테스트 |

다음 단계의 강제 모드는 관찰 결과의 정확도, 지연, 누락 및 잘못된 차단 대상을 충분히 검토하고 별도 승인한 뒤 전환한다. 예산은 경고 후 실행, 상한 대기 30분 경과 알림, 확실한 지시서 오류만 정지하는 정책은 강제 단계에서 구현한다. 세션별 차단기는 처음에 기록만 한다.

## 3차: 실패 안전과 관찰 알림

POSIX 셸 shim은 실제 실행 파일을 먼저 찾는다. 저장소 가상환경 Python(없으면 python3)의 판정은 stdin 없이 별도 프로세스에서 최대 `TH_SHIM_TIMEOUT`초(기본 0.3초)만 수행하며 실패해도 실제 명령을 실행한다. timeout 도구가 없으면 관찰을 생략한다. 실행 인자와 입출력은 원본 명령에 전달된다.
판정 자식에는 `-k` 강제 종료 유예를 적용하고 결과는 임시 파일로 받는다.

유지보수 주기는 상태 DB를 갱신하고 등록되지 않은 코디네이터 유래 관찰 작업의 종료를 inbox에 한 번 알린다. watchd와 직접 사용자 실행은 알리지 않는다. `TH_OBSERVED_NOTIFY=0`으로 종료 알림을 끈다. 작업 결과는 존재하는 FAILED, DONE, STATUS 표식에서 마지막 비어 있지 않은 줄을 사용하며 표식이 없으면 명시한다. 관찰 작업은 재실행하지 않는다.

세션별 상태 DB의 최근 한 시간 토큰 합, 최근 10회 중 재실행 또는 실패 횟수, 같은 위치와 프롬프트 해시 및 실패 분류의 반복을 집계한다. 기본 기준은 각각 300000, 6, 2이며 `TH_BREAKER_TOKENS`, `TH_BREAKER_RETRIES`, `TH_BREAKER_FAILURES`로 설정한다. 기준 도달 시 `breaker_events`와 inbox에 기록하고 같은 원인은 세션별 한 시간에 한 번 알린다. 기록이 있을 때 ths에 최근 24시간 건수를 표시한다. 세션이나 작업 연결이 없는 데이터는 귀속하지 않으므로 집계는 하한이다. 실행을 막지 않는다.

| 경로 | 적용 위치 | 확인 |
| --- | --- | --- |
| 직접 codex / agy | 셸 shim과 제한 시간 자식 | 실패·시간 초과 전달 시험 |
| 모든 관찰 가능 실행 | 유지보수의 상태 색인 | 종료 및 차단기 시험 |
| ths | 상태 DB 차단기 건수 | 상태 출력 회귀 시험 |
| 기존 감시 데몬 및 등록부 | 변경 없음 | 기존 회귀 시험 |

강제 모드 전환 기준: 사용자와 정한 N일 동안 관찰 기록을 수집하고 잘못 판정된 건이 0건임을 확인한 뒤 사용자의 별도 승인을 받는다. 강제 모드에서만 상한 대기가 30분을 넘으면 inbox에 알린다. 관찰 모드에는 대기가 없다.

## 정책 변경 알림

전역 적용은 이전 정책과 설치한 현재 정책을 SHA-256 이름으로 `~/.team-harness/policy_history`에 저장하고 최근 20개를 유지한다. 기존 세션의 이전 본문이 있으면 다음 입력에서 절 제목과 변경된 줄을 최대 30줄로 알리고 전문 경로를 안내한다. 이전 본문이 없으면 전문을 전달한다. 세션 시작과 중복 전달 동작은 기존과 같다.
