# 전역 자동 적용

사용자가 th cord와 ths만 사용해도 실행 관찰과 이력 조회가 적용되어야 한다.

- 이미 전역 적용: 기존 hook과 공유 유지보수.
- 실행 후 관찰: 동일 사용자의 프로세스와 환경을 읽어 출처를 복원하고 색인한다. 원본 등록부와 실행 제어는 변경하지 않는다.
- 실행 전 가로채기: 다음 단계에서 PATH 앞 shim을 두며 처음에는 판정만 기록하는 관찰 모드로 운영한다.
- 명시 명령: ths, th-db, th-why로 조회한다.

예산 초과는 경고 후 실행하고 상한 대기가 30분을 넘으면 inbox에 알린다. 반드시 실패할 지시서 오류만 실행 전 정지한다. 같은 일의 반복 실패 2회에 정지하고 실행 깊이를 제한한다. 관찰로 편입된 작업은 자동 재실행하지 않으며 세션별 차단기는 처음에는 기록만 한다.

1차는 실행 후 관찰, 상태 DB와 코디네이터 자동 조회다. 실행 전 제어는 다음 단계다. 롤백 기준은 `checkpoint-20261112-pre-global` 태그다.

## 2차: 실행 전 관찰

배포는 `~/.team-harness/shim/bin`에 저장소의 `codex`, `agy`를 링크하고 `.bashrc`, `.profile`의 관리 블록으로 PATH 앞에 추가한다. 기존 셸에는 적용되지 않는다. `th-sync.sh --status`의 `shim`으로 확인하고 `th-sync.sh --remove-shim`으로 관리 블록과 해당 링크를 제거한다. `claude`는 변경하지 않는다.

대화형 codex, `th-launch.sh` 자손, `TH_SHIM=0`은 기록 없이 통과한다. 직접 비대화형 실행은 기존 정책 판정과 지시서 검사를 관찰하고 같은 PID로 원래 프로그램을 실행한다. stdin은 읽지 않으며 점검 불가로 기록한다. 예외나 잠금은 실행을 막지 않는다. `TH_SHIM_MODE`와 관계없이 이번 구현은 관찰만 수행한다. 깊이는 `TH_SHIM_DEPTH`로 전달한다. DB에 프롬프트 자체 대신 해시를 저장한다. 반복 실패는 상태 DB에 색인된 동일 작업 실패만 셀 수 있으며 직접 실행의 종료 결과는 exec 이후 알 수 없다. 관찰된 작업은 자동 재실행하지 않는다.

| 경로 | 적용 위치 | 확인 |
| --- | --- | --- |
| 직접 codex exec / 비대화형 agy | PATH shim | 가짜 실행 파일과 실제 셸 테스트 |
| th-launch | 기존 실행 전 정책, shim 통과 | 조상 우회 테스트 |
| 내장 조율자·SDK·protocol | 기존 정책 및 직접 CLI 호출 시 shim | 기존 회귀 테스트 |
| ths / watch | DB 관찰 건수 표시 / 기존 프로세스 관찰 | 상태 출력 테스트 |

다음 단계의 강제 모드는 관찰 결과의 정확도, 지연, 누락 및 잘못된 차단 대상을 충분히 검토하고 별도 승인한 뒤 전환한다. 예산은 경고 후 실행, 상한 대기 30분 경과 알림, 확실한 지시서 오류만 정지하는 정책은 강제 단계에서 구현한다. 세션별 차단기는 처음에 기록만 한다.
