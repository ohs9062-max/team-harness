# 작업자 판단 결과를 되돌릴 수 있게 만들기 (Worker judgment durability guide)

## 상태 및 목적 (Status and purpose)

이 문서는 TH-D11("작업자의 판단 산출물은 코드가 아니므로, 명시적으로 캡처하지 않는 한 git으로 되돌릴 수 없다")에 대한 **소비자용 실천 가이드**입니다. 다른 TH-D 설계 문서와 달리 이 문서는 team-harness 자체의 내부 동작을 규정하지 않습니다 — team-harness 코드를 전혀 바꾸지 않고도, 지금 이 순간부터 소비자가 적용할 수 있는 패턴을 설명합니다.

## 문제

조율자가 작업자에게 자연어 프롬프트로 위임한 작업(이미지 판단, 분류, 좌표 추출, 요약 등)의 결과는 코드 diff가 아닙니다. 같은 프롬프트를 다시 실행해도 같은 결과가 나온다는 보장이 없으므로, "재실행"은 "복원"이 아닙니다. 이전 판단으로 되돌리려면 그 판단의 원시 산출물이 **어딘가에 실제로 저장돼 있어야** 합니다.

## 이미 존재하는 재료

team-harness는 이미 필요한 걸 다 준비해서 소비자에게 넘겨줍니다. 코드 변경이 필요 없습니다:

- `TeamHarnessResult.agents`의 각 `AgentRecord`는 `stdout_log`/`stderr_log` **경로**를 담고 있습니다. 이건 `run.json`처럼 8KB로 잘리지 않은 작업자의 **전체 원본 출력**입니다(TH-D2: 작업자의 stdout/stderr는 파일로 리다이렉트됨).
- `session_id`가 캡처되면(TH-D4) 해당 논리 세션을 나중에 재개할 수도 있지만, 재개는 "이어서 진행"이지 "그 시점 판단으로 되돌리기"가 아님에 유의하십시오.

빠져 있는 건 코드가 아니라 **관례**입니다: 이 파일이 `~/.team-harness/runs/`(프로젝트 저장소 바깥, 운영용 임시 디렉터리)에만 남아있고 아무도 프로젝트 저장소로 옮겨 커밋하지 않는다는 점입니다.

## 패턴: git으로 버전관리되는 판단 캐시

1. 작업 단위를 식별할 수 있는 **안정적인 키**를 정하십시오(파일 ID, 요청 ID, 프레임 번호 등). 같은 키로 다시 판단을 요청하면 같은 파일을 다시 만들어야 합니다.
2. `spawn_agent`/`wait_for_agents` 이후, 해당 작업자의 `stdout_log`에서 최종 판단만 추출해 **프로젝트 저장소 안**의 캐시 디렉터리에 저장하십시오 (예: `<project>/judgment_cache/<키>.json`).
3. 기존 파일을 덮어쓰지 말고 **버전을 남기십시오** — 두 가지 방법이 있고 어느 쪽이든 좋습니다:
   - 파일명에 버전을 붙인다 (`<키>_v2.json`, `<키>_v3.json`, ...) 그리고 "최선의 버전"을 고르는 우선순위 규칙을 소비자 코드에 둔다.
   - 또는 파일명을 고정하고 매번 git 커밋을 남긴다 — 그러면 `git log -p`/`git checkout <이전 커밋> -- judgment_cache/<키>.json`이 곧 롤백이 됩니다.
4. 판단 로직(프롬프트, 후처리 코드)을 고칠 때는 **캐시를 재사용해서 재빌드**하십시오 — 새 작업자 호출 없이 이미 저장된 판단 + 바뀐 후처리 로직만으로 결과를 다시 만들 수 있어야 합니다. 이래야 로직 버그 롤백과 판단 결과 롤백이 서로 얽히지 않습니다.

## 실제 사례

이 패턴은 이론이 아니라, off-road 로봇 주행 데이터셋 라벨링 파이프라인(Codex 비전 판단 + 로컬 SAM2 세그멘테이션)에서 그대로 검증됐습니다. 각 프레임의 Codex 판단은 `codex_cache/frame_XXXXXX_codex_vN.jsonl`로 버전별로 저장됐고, 세그멘테이션 후처리 로직을 여러 차례 고치는 동안 **새 작업자 호출 없이** 캐시된 판단을 재사용해 50개 프레임 전체를 반복적으로 재빌드했습니다. 로직 버그(예: 후드 폴리곤 오차)를 고칠 때마다 판단 자체를 다시 요청할 필요가 없었고, 반대로 특정 프레임의 판단 자체가 잘못됐을 때(예: 후드 위에 찍힌 점)는 그 프레임의 캐시 파일만 수정하고 다른 49개는 그대로 뒀습니다. 로직 롤백과 판단 롤백이 분리되지 않았다면 두 종류의 수정이 서로를 덮어썼을 것입니다.

## 이 패턴으로도 안 되는 것

- **처음부터 캡처되지 않은 판단은 복원할 수 없습니다.** 이 가이드는 "앞으로의 판단을 되돌릴 수 있게" 만드는 것이지, 이미 지나간 미캡처 판단을 소급 복구해주지 않습니다.
- **재실행이 복원을 대체하지 않습니다.** 캐시가 없어서 같은 프롬프트를 다시 던지면, 그건 "복원"이 아니라 "새로운 판단"입니다 — 이전 것과 다를 수 있고, 다르다는 사실 자체를 알아챌 방법도 없습니다.
- team-harness는 이 캐시 디렉터리를 강제하거나 대신 관리하지 않습니다(TH-D1). 어떤 키로 캐시할지, 언제 재사용할지는 전적으로 소비자의 판단입니다.
